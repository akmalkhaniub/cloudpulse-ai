Structured Product Feedback for Amazon Developer & Bedrock Engineering Teams

        
Actionable friction points, schema observations, and feature requests gathered while building CloudPulse AI on Alexa+ MCP and Amazon Bedrock Converse API.

      


      

        

          
1. Alexa+ MCP Server Schema Alignment

          

            Friction: Mapping MCP `inputSchema` (JSON Schema Draft-07) to Bedrock Converse `toolSpec.inputSchema.json` requires manual wrapper conversion.


            Recommendation: Provide a native `@amazon-alexa/mcp-bedrock-bridge` utility that automatically translates MCP `tools/list` descriptors into Bedrock `ConverseCommand` `toolConfig` definitions and Alexa+ voice slot types.
          

        

        

          
2. Bedrock Converse Model ID Portability

          

            Friction: Cross-region inference profile prefixes (`us.anthropic...`) vs direct foundation model IDs (`amazon.nova-pro-v1:0`) behave differently depending on account marketplace entitlements.


            Recommendation: Add a `ConverseCapabilities` discovery call in `@aws-sdk/client-bedrock-runtime` that returns the account's currently callable tool-use models without trial-and-error invocation.
          

        

        

          
3. Local Web Simulator for Gated Alexa+ Skills

          

            Friction: Because the Alexa+ Developer Console is currently gated to preview partners, developers building self-hosted MCP servers must build custom voice-to-JSON-RPC test harnesses.


            Recommendation: Ship an offline CLI simulator (`alexa-mcp-sim`) that emulates Alexa+ multi-turn tool orchestration and SSML speech rendering against any local `/api/mcp` endpoint.
