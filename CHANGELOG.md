# Changelog

## [Unreleased]

### Fixed (2026-10-23, final QC)
- "Fix it" on an empty or clean manifest no longer stages an empty PR; it says why nothing was opened.
- Morning briefing no longer claims "zero high-risk exposures" when HIGH findings exist without a CRITICAL one,
  and handles empty manifests.
- MCP: `ping` implemented; missing required tool arguments return `isError` instead of running with empty input.
- Live GitHub PRs now need an explicit `CLOUDPULSE_LIVE_PR=true` in addition to `GITHUB_TOKEN`, so a token
  in a developer's environment never opens a PR by accident.
- PR descriptions record human approval instead of asking for it again; the model keeps conditional wording.
- MCP tool titles and server info no longer present the Bee / Fire TV concepts as Amazon integrations.
- Removed the ffmpeg dev dependency (video-production tooling moved out of the repo); archived the outdated
  `ROADMAP.md` and `SPECIFICATION.md`.

### Added (2026-10-23) — Change Safety Engine
- `src/change_safety.ts`: classifies every fix as SAFE / CAUTION / DISRUPTIVE from documented AWS / Terraform behavior
  (in place, restart, or replacement), with downtime, data risk, guards, and a "before you merge" checklist.
- Approval gate: `ship_github_remediation_pr` holds disruptive fixes back unless `approveDisruptive: true`.
  Voice flow: "Fix it" ships safe fixes, "Approve the database change" includes the rest.
- New MCP tool `assess_change_risk` (7 tools total) and a "Is it safe to fix everything?" voice intent.
- Safety guards written into patches: RDS `skip_final_snapshot = false` + `final_snapshot_identifier`;
  Multi-AZ `apply_immediately = false`; SSH CIDR inferred from an `aws_vpc` in the manifest when present.
- Verification: every PR re-audits the patched code and reports findings before → after.
- Amazon Nova Pro writes each PR's summary and rollout plan (`writeChangeBrief`); the risk table and checklist
  are always generated by code. Template fallback without credentials.
- Web console: Change Plan panel (ship now vs. needs approval, re-scan badge, approve button, PR description),
  risk badges on every finding.
- `test/safety.test.ts` (15 assertions) and 4 new integration assertions (approval flow, risk intent,
  outputSchema conformance for every tool). 62 assertions total.
- `npm run mcp:inspect`: official MCP Inspector CLI against the running server.

### Fixed (2026-10-23)
- **EC2 rightsizing could produce an unbootable instance:** it switched x86 `m5.4xlarge` to Graviton `t4g.xlarge`
  while keeping the x86 AMI. It now stays in the same family (`m5.4xlarge → m5.xlarge`); savings are $420.48/mo.
- **MCP compatibility:** `_meta` moved from the JSON-RPC envelope into `result` (the official SDK rejected it);
  notifications get `202 Accepted`; `initialize` negotiates the version instead of erroring.
- **Output schemas:** 3 tools declared fields they never returned; all 7 now match and are tested.
- Voice router: word-boundary matching (e.g. "been" no longer triggers the Bee intent).

### Fixed (2026-10-22)
- **Invalid RDS encryption patch:** the synthesizer inserted `storage_encrypted = true` without removing
  the existing `storage_encrypted = false`, which produced duplicate attributes. Fixes now edit attributes in place,
  scoped to the offending resource block.
- **Diff output:** replaced the line-index diff with an LCS-based unified diff (proper hunks, `-` before `+`,
  `\ No newline at end of file`). Patches now apply with `git apply`.
- **Combined patch:** "fix all" now emits ONE applicable diff instead of one diff per finding against the same file.
- Added remediations for `REL_NO_MULTI_AZ_DB` and `SEC_UNENCRYPTED_EBS`. Rules with no safe auto-fix return no diff.
- Spoken replies: currency formatting and singular/plural; no raw model IDs in speech.
- UI: color-coded diffs, pillar labels (Reliability no longer shown as "Security Guardrail"), no blocking `alert()`
  on copy, header status pill no longer overlaps the logo on narrow screens.
- Deploy configs now default to `amazon.nova-pro-v1:0` (they still named Claude 3.5 Sonnet).

### Migrated to TypeScript (2026-09-18)
- Ported IaC parser, Well-Architected engine, remediation synthesizer, Bedrock
  Converse agent, and server from JavaScript to **TypeScript** (strict) with typed
  resources, findings, and Converse result shapes.

### Fixed
- **Live Bedrock mode never worked**: `runConverseTurn` called `processBedrockResponse`,
  which was never defined — every live attempt threw and silently fell back to the
  simulator. Implemented a real Converse tool-use loop (execute toolUse blocks, feed
  toolResult blocks back for a final turn) and normalized the response.

### Added
- Real `@aws-sdk/client-bedrock-runtime` dependency so live mode genuinely works
  when AWS credentials are present; deterministic simulator fallback otherwise.
- Server integration suite (`test/server_integration.ts`, 9 assertions): health,
  /api/audit (Converse), /api/remediate, and security guards.
- Security: path-traversal guard (403), 256 KB request-body cap (413), input validation.
- `createCloudPulseServer()` factory (testable), graceful shutdown, CI, multi-stage
  Dockerfile, `engines.node >= 18`.

### Notes
- With no AWS credentials the agent runs a deterministic simulator that adheres to the
  Bedrock Converse schema; set AWS credentials + Bedrock model access for live calls.
